接入前准备

  • 宿主客户端完成用户登录并获得 liveUserId、imUserId、liveToken。
  • 宿主动态传入 sceneType：1 直播间，2 IM 群。
  • 宿主动态传入 sceneId，SDK 不内置固定场景。
  • 正式环境必须使用 HTTPS/WSS。

5 分钟快速接入

  1. 在 settings.gradle.kts 添加 GitHub Maven 仓库。
  2. 在 App 模块添加 game-sdk:0.5.0。
  3. 在主进程 Application 初始化 SDK。
  4. 客户端登录后创建 GameSessionConfig。
  5. 调用 openGame(activity, "niuniu", session)。
maven {
    url = uri("https://raw.githubusercontent.com/eathwinster-jk/cocos-game-android-sdk/main/repository")
}

implementation("com.eath.cocosgamesdk:game-sdk:0.5.0")
CocosGameSDK.getInstance().initialize(applicationContext)

val session = GameSessionConfig(
    websocketUrl, apiBaseUrl, liveUserId, imUserId, liveToken,
    sceneType, sceneId, 0, BuildConfig.VERSION_NAME, "Android"
)
CocosGameSDK.getInstance().openGame(activity, "niuniu", session)

SDK 不提供生产登录。UID、Token、Scene Type、Scene ID 必须由宿主客户端传入。

游戏下方宿主内容

竖屏时游戏画面下方依次是 SDK 内置的加注筹码卡片和宿主内容区。宿主内容（直播、聊天等）通过 GameBottomContentProvider 提供，全屏时自动隐藏，退出全屏恢复；未设置时内容区为空白。注册 setBetListener 后竖屏不再显示 SDK 加注卡片，由宿主实现，见竖屏宿主实现。在 openGame 之前设置：

Java

CocosGameSDK.getInstance().setBottomContentProvider((activity, gameId) -> {
    // 返回 null 表示不显示
    return createHostBottomView(activity);
});

Kotlin

CocosGameSDK.getInstance().setBottomContentProvider { activity, gameId ->
    createHostBottomView(activity)
}
  • 每次打开游戏页调用一次，需返回新的 View。
  • 不要持有传入的 Activity，游戏页关闭后即失效。
  • 示例实现见 Demo 源码 DemoBottomContentProvider.java。

迷你条

宿主可把牌桌缩成顶部 362:50 的横条，下方宿主内容随之上移。迷你条显示局数、阶段、头像、手牌与结算输赢、余额、展开和退出按钮；入座时显示自己，旁观时显示庄家，无庄家时显示问号头像。

  • setMiniMode(true) 缩小，setMiniMode(false) 恢复；游戏页未打开时忽略。
  • 玩家点击迷你条展开按钮时，SDK 自动恢复牌桌，宿主无需处理。
  • 退出按钮与牌桌返回按钮行为一致。
  • 迷你模式下不可切换全屏，处于全屏时进入迷你条会先退出全屏。
  • 状态变化（宿主切换或玩家点击展开）通过 GameHostListener.onMiniModeChanged(gameId, isMiniMode) 回调，默认空实现。

Java

CocosGameSDK.getInstance().setMiniMode(true);

CocosGameSDK.getInstance().setHostListener(new GameHostListener() {
    @Override
    public void onMiniModeChanged(String gameId, boolean isMiniMode) {
        // 同步宿主自己的按钮状态等
    }
});

Kotlin

CocosGameSDK.getInstance().setMiniMode(true)

CocosGameSDK.getInstance().setHostListener(object : GameHostListener {
    override fun onMiniModeChanged(gameId: String, isMiniMode: Boolean) {
        // 同步宿主自己的按钮状态等
    }
})

嵌入宿主页面（View 接入）

保留宿主自己的直播详情页、群聊页，只把牌桌放进页面里的一个容器（与 iOS 一致）。牌桌铺满容器，容器尺寸由宿主控制，推荐宽高比 375:211。原有 openGame(activity, gameId, session) 独立游戏页保持不变。

  • 宿主 Activity 须在 Manifest 声明 android:configChanges="orientation|keyboardHidden|screenSize|screenLayout|smallestScreenSize"，否则横屏全屏会重建页面，SDK 会拒绝全屏并打印错误日志。
  • 宿主 onBackPressed 须先调用 CocosGameSDK.getInstance().onBackPressed()：全屏时退回竖屏、在座时由游戏确认离座，返回 false 再走宿主自己的返回。
  • toggleFullscreen()：牌桌移到窗口顶层铺满并把页面转为横屏，退出时放回容器并恢复原方向与系统栏。
  • 迷你条：在 onMiniModeChanged 中把容器调整为 362:50（或恢复 375:211）。
  • closeGame() 释放牌桌并移出容器；宿主页面销毁时 SDK 自动释放；同一时间只能打开一个牌桌。
  • 钱包余额变化通过 onGameEvent 发送 wallet.balance_changed，载荷 {"balanceCent":995420}。
GameHostListener 回调说明
onGameEvent通用事件，含钱包余额变化
onMiniModeChanged迷你条变化，宿主调整容器高度
onFullscreenChanged横屏全屏变化
onPlayingStateChanged是否在座参与本局
onBackRequested牌桌请求返回；返回 true 表示宿主自行处理并负责 closeGame，默认由 SDK 关闭
onSessionInvalid会话失效，SDK 随后关闭牌桌
onGameClosed牌桌已关闭并移出容器

Java

// 宿主 Activity 须在 Manifest 声明：
// android:configChanges="orientation|keyboardHidden|screenSize|screenLayout|smallestScreenSize"
CocosGameSDK.getInstance().setHostListener(this);
CocosGameSDK.getInstance().openGame(this, tableContainer, "niuniu", session);

@Override
public void onMiniModeChanged(String gameId, boolean isMiniMode) {
    tableContainer.setLayoutParams(createTableParams(isMiniMode)); // 375:211 或 362:50
}

@Override
public void onGameClosed(String gameId) {
    finish();
}

@Override
public void onBackPressed() {
    if (CocosGameSDK.getInstance().onBackPressed()) return;
    super.onBackPressed();
}

Kotlin

CocosGameSDK.getInstance().setHostListener(this)
CocosGameSDK.getInstance().openGame(this, tableContainer, "niuniu", session)

竖屏界面由宿主实现

竖屏下的下注、记录与规则、退出确认都可以由宿主自绘；注册对应监听后竖屏 SDK 不再展示这些界面，全屏仍由 SDK 展示。未注册的监听仍使用 SDK 自带界面。独立游戏页与嵌入模式均适用。

界面监听宿主调用
下注setBetListener：onBetOptions（注区、筹码、截止时间）、onBetClosed、onBetResultsubmitBet(roundId, areaCode, amountCent, clientBetNo)
记录与规则setRecordsListener：onShowRecords、onRecordsUpdatedqueryRecords(isHistory, filterKey, periodIndex, keyword)、loadMoreRecords(isHistory)
退出确认setExitListener：onExitRequestedGameExitDecision.leave() / stay()
  • submitBet 须在主线程调用；clientBetNo 为幂等号（不超过 64 个字符，可用 CocosGameSDK.createClientBetNo() 生成），同一幂等号在结果返回前或成功后再次提交会被忽略，失败后可用原幂等号重试；本局已截止、游戏未打开或幂等号重复时返回 false。
  • 记录查询：isHistory 为 false 查本桌当前记录，filterKey 取 records.filters[].key（全部为 all）；为 true 查历史场次，periodIndex 取周期下标，keyword 为局号或桌号。
  • 退出确认必须调用 leave() 或 stay() 之一，只有第一次生效；游戏只允许在两局之间离座。
  • 示例见 Demo 源码 DemoHostBetPanel、DemoHostRecordsSheet、DemoBottomContentProvider。

CocosGameSDK.getInstance().setExitListener { _, decision ->
    AlertDialog.Builder(activity)
        .setTitle("确认离开牌桌？")
        .setPositiveButton("离开") { _, _ -> decision.leave() }
        .setNegativeButton("继续游戏") { _, _ -> decision.stay() }
        .setOnDismissListener { decision.stay() }
        .show()
}

交互时序

以下回调仅在手机竖屏内嵌（非全屏）时触发，全屏时由游戏内弹窗展示；收到 GameHostListener.onFullscreenChanged 进入全屏时，建议宿主收起自绘的下注和记录面板。游客不会触发下注与记录回调，改为发送 auth.login_required。

时机SDK / 宿主调用宿主处理
进入下注阶段（每局一次）回调 GameBetListener.onBetOptions显示下注面板：注区、筹码、倒计时
玩家选注区和筹码宿主调用 submitBet(roundId, areaCode, amountCent, clientBetNo)结果经 onBetResult 返回，按 clientBetNo 对应
下注截止或离局回调 onBetClosed收起下注面板
玩家点击记录与规则回调 GameRecordsListener.onShowRecords(gameId, rulesJson)打开记录面板，首屏数据在 records 字段
切换本桌 / 历史、筛选、搜索宿主调用 queryRecords(isHistory, filterKey, periodIndex, keyword)先回调 onRecordsUpdated(gameId, recordsJson)（list.status 为 loading），查询完成再回调一次
滑到列表底部宿主调用 loadMoreRecords(isHistory)结果经 onRecordsUpdated(gameId, recordsJson) 返回，整份替换即可
关闭记录面板无需通知游戏宿主自行关闭

记录数据字段

展示记录回调与记录更新回调的 JSON 由游戏统一生成，三端一致；文案均已本地化，宿主直接展示即可。

字段说明
title / roomTag规则标题、房间标签（仅展示记录回调）
sections[]规则分组：title、items[]（title、value、description）（仅展示记录回调）
records首屏记录，结构同下（仅展示记录回调；记录更新回调直接是这份结构）
currentTab / historyTab「本桌」「历史」页签文字
filters[]下注类型筛选 { key, label }，全部为 all；查询时传 filterKey
current.items[]本桌每局：title、detail、result、tone、type
current.banner / stats[]本桌提示条、统计项 { label, value, tone }
history.sessions[]历史场次：key、title、amount、tone、detail、source、daysAgo、types[]、rounds[]（结构同 current.items）
history.periods[]时间范围 { label, days }，查询时传下标 periodIndex
history.sources[] / searchPlaceholder / searchButton来源列表、搜索框占位与按钮文字
current.list / history.list列表状态：status（loading / ready / error）、hasMore、isLoadingMore、message（错误信息）
emptyText / footer空状态文字；底部文字 loading、loadMore、noMore、retry
tone金额颜色：win / lose / draw / normal
  • 界面状态：list.status 为 loading 时显示加载中；为 error 时显示 message 与重试（重试即再次查询）；列表为空显示 emptyText；hasMore 为 true 且未在加载时，滑到底部加载更多。
  • SDK 自带界面会再按 daysAgo（所选时间范围）、source、搜索关键字与 types 在本地过滤 history.sessions，宿主可参照实现。

游客观战（直播间与群聊）

未登录用户可以游客身份进入直播间或 IM 群观战（群聊游客 0.2.4 起支持）。游客只能观战：牌桌不显示右上角余额，下注阶段不弹下注窗，也不通知宿主。

auth.login_required 载荷触发操作
{"action":"join"}点击立即加入
{"action":"records"}点击记录与规则
{"action":"fullscreen"}点击全屏（旋转大屏），不会进入全屏
  • 需要登录的操作统一通过 GameHostListener.onGameEvent 发送 auth.login_required，游戏内不弹提示，由宿主提示登录。
  • 建议留在游戏页提示登录或拉起登录页；登录成功后再 closeGame()，并用登录会话重新 openGame。不要在事件回调里直接关闭牌桌。
  • deviceId 由宿主生成并保持稳定，例如 "android-" + ANDROID_ID。

Java

String deviceId = "android-" + Settings.Secure.getString(getContentResolver(), Settings.Secure.ANDROID_ID);
GameSessionConfig session = GameSessionConfig.createGuest(
    "wss://test.imnono.net/game-ws/ws",
    "https://test.imnono.net/game-lobby",
    deviceId,
    2,              // 场景类型：1 直播间，2 IM 群
    sceneId,        // 直播间编号或群号
    0,
    BuildConfig.VERSION_NAME,
    "Android");
CocosGameSDK.getInstance().openGame(this, tableContainer, "niuniu", session);

@Override
public void onGameEvent(String gameId, String event, String payloadJson) {
    if (GameEvents.LOGIN_REQUIRED.equals(event)) {
        showLoginPrompt();
    }
}

客户端与 SDK 职责

客户端负责

  • 账号登录、Token 刷新和退出。
  • UID、Token、Scene Type、Scene ID。
  • 游戏入口、权限和风控判断。
  • 会话失效后返回登录流程。
  • 决定是否执行横竖屏切换。
  • 自定义钱包、充值或其他业务页面。

SDK 负责

  • Cocos Activity 和游戏模块加载。
  • 大厅 HTTP、WebSocket、重连和快照恢复。
  • 游戏资源、音频和生命周期。
  • 入座、下注、结算与界面状态。
  • 容器尺寸回传和游戏等比适配。
  • 固定退出、下注与通用事件桥。

Demo 登录模式

账号密码

Demo 调用测试登录接口，将服务端返回的 UID、Token 注入 GameSessionConfig。账号密码不写入 SDK，也不持久化。

UID Token

直接输入已有 UID、Token。两种模式都需要客户端输入或确认 Scene Type、Scene ID。

账号密码登录仅用于 Demo。正式客户端必须复用自身登录体系。

热更新接入（可选）

AAR 内置游戏模块。0.3.0 起热更新是独立的库，与核心 SDK 同版本发布，不引入时始终使用内置模块。完整说明与 Demo 见 cocos-game-hotupdate-demo。

// 热更新库会自动带上同版本 game-sdk
implementation("com.eath.cocosgamesdk:game-sdk-hotupdate:0.5.0")
CocosGameSDK.getInstance().initialize(context);
// 第三个参数是清单签名公钥（0.5.0 起），由 SDK 发布方提供
GameHotUpdate hotUpdate = GameHotUpdate.install(context, catalogUrl, catalogPublicKey);
hotUpdate.setUpdateListener(updateListener); // 可选，主线程回调
hotUpdate.checkForUpdate("niuniu");          // 可选，提前下载
int version = hotUpdate.getInstalledVersion("niuniu"); // 下次打开会使用的模块版本，0 为内置
hotUpdate.clearInstalledModules("niuniu"); // 关闭游戏后清除已下载模块，游戏打开或下载中返回 false
状态说明
checking正在拉取版本清单
downloading正在下载模块包
installed新版本已安装，下次打开游戏生效
upToDate没有可安装的新版本

版本清单地址由 SDK 发布方提供，必须为 HTTPS。更新失败不影响打开游戏，SDK 继续使用已安装或内置版本。错误码：1 网络（已自动重试）、2 清单格式、3 校验失败、4 安装失败、5 已取消、6 空间不足、7 清单签名校验失败。

0.5.0 起：有旧版本或内置模块时优先下载增量补丁，下载按分片进行并支持断点续传，补丁失败自动改下完整包；埋点事件见 GameUpdateListener.onUpdateEvent，包含 updateType（full / patch）与 baseVersion。宿主接口不变。

生命周期、旋转与弹窗

  • 进入后台时 SDK 暂停音频和实时连接；回前台重新同步权威桌态。
  • 旋转按钮只向客户端发请求，是否旋转由客户端决定。
  • 客户端完成布局后回传实际游戏容器宽高，游戏只负责界面适配。
  • SDK 内置退出确认和下注卡；钱包、充值等业务页面通过公共事件接入。
  • 规则弹窗关闭、大屏切小屏后应继续验证全部按钮可点击。

我的记录接入

「我的记录」由 SDK 内置实现，客户端无需调用任何新 API、无需注册回调，升级到 v0.1.4 及以上即可使用。用户在游戏内点击「规则」按钮，切换到「我的记录」页签即可查看本人注单，页面以原生弹窗展示。v0.2.0 起也可注册 setRecordsListener 由宿主自绘竖屏记录弹窗，见竖屏宿主实现。

工作方式

  • SDK 使用 GameSessionConfig 中的 apiBaseUrl、liveUserId、liveToken 直接请求后台，请求头与入座、下注接口相同（live-user-id、live-user-token）。
  • 当前本桌：POST /api/lobby/bet/table/mine，按当前桌号查询，游标分页。
  • 历史场次：POST /api/lobby/bet/history，按下注日期区间查询，游标分页。
  • 每页 20 条，列表滑到底部自动加载下一页；加载失败显示点击重试，无数据显示空状态。
  • 顶部场景标签取自 sceneType、sceneId 和实际进入的桌号。

页面功能

页签功能
当前本桌本桌完成局数、本人赢/输、本人净输赢；全部 / 在座下注 / 观战跟注筛选
历史场次最近 30 天 / 最近 7 天 / 今天；桌号、局号搜索；按桌台和日期分组，净输赢为扣除抽成后金额；顶部展示区间完成局数、赢/输与净输赢

客户端需确认

  • apiBaseUrl 指向的大厅网关已开放上述两个接口，且与入座、下注使用同一环境。
  • liveToken 在游戏期间保持有效；Token 失效时记录页显示加载失败，点击可重试。
  • 记录只展示当前登录用户本人的注单，不涉及其他用户数据。

常见问题

Gradle 无法下载

确认可访问 raw.githubusercontent.com，然后执行 ./gradlew --refresh-dependencies。

x86 模拟器不能运行

当前 SDK 仅包含 arm64-v8a，请使用 ARM 模拟器或 ARM64 真机。

提示 sessionConfig 不能为空

SDK 不允许无会话启动。客户端必须先传入 UID、Token、Scene Type、Scene ID。

会话认证失败

确认 UID 与 Token 匹配、未过期，HTTP 与 WebSocket 属于同一环境。

我的记录加载失败或为空

确认大厅网关已开放 /api/lobby/bet/table/mine 与 /api/lobby/bet/history，Token 未过期；当前本桌需先成功进入桌台，历史场次可切换为最近 30 天查看。

找不到桌台

确认 Scene Type、Scene ID 以及后台开桌场景完全一致。

AAR 冲突或找不到 native 库

确认仅保留一个 SDK 版本、启用 arm64-v8a，并检查 APK 中存在 lib/arm64-v8a/libcocos.so。
